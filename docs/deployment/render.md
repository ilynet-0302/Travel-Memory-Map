# Render deployment

The recommended portfolio setup is:

- frontend: GitHub Pages;
- backend: Render Web Service in Frankfurt;
- database, authentication and photo storage: the existing Supabase project.

## Create the backend service

1. Sign in to Render with GitHub and connect the `Travel-Memory-Map` repository.
2. Choose **New > Blueprint** and select the repository.
3. Render detects the root `render.yaml` and creates `travel-memory-api` in Frankfurt.
4. Before the first deploy, start the backend locally once with the existing database administrator
   credentials so Flyway applies every migration, including `V12__harden_data_api_access.sql`.
5. In Supabase SQL Editor, run `docs/deployment/create-runtime-role.sql` after replacing its password
   placeholder with a long password generated by a password manager.
6. Enter every environment variable marked `sync: false` in the Render form.
7. Never copy `.env` into the repository or Docker image.

Use the values from the local `.env`, with these production differences:

- `CORS_ALLOWED_ORIGINS` must be the final HTTPS GitHub Pages origin only;
- `DATABASE_URL` should use the shared session pooler on port `5432` and include `sslmode=require`;
- `DATABASE_USERNAME` is `travel_memory_app.PROJECT_REF` when the Supavisor pooler is used;
- `DATABASE_PASSWORD` is the runtime-role password from step 5, not the Supabase `postgres` password;
- `SPRING_FLYWAY_ENABLED=false` keeps migration/admin privileges out of the running web service;
- keep Supabase Data API disabled;
- keep `SUPABASE_AUTH_AUDIENCE=authenticated`;
- keep `SUPABASE_SIGNED_URL_TTL_SECONDS=900`.

The service health check is `GET /actuator/health`. A successful deployment returns a JSON response
with `status` equal to `UP` without exposing database details.

## Connect the frontend

After Render assigns the `https://...onrender.com` address, configure these GitHub repository variables:

- `VITE_API_BASE_URL=https://YOUR-SERVICE.onrender.com/api/v1`
- `VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co`
- `VITE_SUPABASE_PUBLISHABLE_KEY=YOUR-PUBLISHABLE-KEY`
- `VITE_DEMO_MODE=false`

Then set `CORS_ALLOWED_ORIGINS` in Render to the exact GitHub Pages origin and redeploy the backend.
Finally, add the GitHub Pages URL to the allowed redirect URLs in Supabase Auth.

For future schema changes, apply the Flyway migration from a trusted local machine using the database
administrator account before deploying the corresponding backend version. Render's pre-deploy command is
available only on paid web services, so the free service deliberately does not retain migration credentials.
